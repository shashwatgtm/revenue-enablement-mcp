Who is Account Plan Builder not ideal for?

  • Anyone who cannot give the required inputs (Account name); the answer is built only from them.
  • Teams that want the tools to read their CRM, email or call notes: they work only from what you type.
  • Sending anything straight to a buyer: every output is a draft for a person to review first.

How do I use Account Plan Builder from Claude?

Connect Revenue Enablement once (see Connect), then ask in plain words. A prompt built from the tested example:

Use Revenue Enablement's Account Plan Builder tool. account name: Example Clinic Group; industry: healthcare; current arr: 24000; your solution: ExampleCo Scheduler.

MCP tool name: account_plan_builder. REST: POST https://revenue-enablement.gtmhelix.com/api/tools/account_plan_builder with this JSON body (see Docs):

{
  "input": {
    "account_name": "Example Clinic Group",
    "industry": "healthcare",
    "current_arr": 24000,
    "your_solution": "ExampleCo Scheduler"
  }
}

How does Account Plan Builder work?

It applies fixed rules in the Revenue Enablement code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server call the same tool code, so the same input gives the same answer in both.
