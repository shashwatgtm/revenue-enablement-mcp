Structure a win/loss review of one deal or a set of deals: organizes the deal details you provide and returns the factors and questions to investigate.

Who is Win/Loss Analyzer not ideal for?

  • Anyone who cannot give the required inputs (Analysis type); the answer is built only from them.
  • Teams that want the tools to read their CRM, email or call notes: they work only from what you type.
  • Sending anything straight to a buyer: every output is a draft for a person to review first.

How do I use Win/Loss Analyzer from Claude?

Connect Revenue Enablement once (see Connect), then ask in plain words. A prompt built from the tested example:

Use Revenue Enablement's Win/Loss Analyzer tool. analysis type: single deal; deal outcome: lost; loss reason: price; competitor won: Competitor A; deal value: 30000.

MCP tool name: win_loss_analyzer. REST: POST https://revenue-enablement.gtmhelix.com/api/tools/win_loss_analyzer with this JSON body (see Docs):

{
  "input": {
    "analysis_type": "single_deal",
    "deal_outcome": "lost",
    "loss_reason": "price",
    "competitor_won": "Competitor A",
    "deal_value": 30000
  }
}

How does Win/Loss Analyzer work?

It applies fixed rules in the Revenue Enablement code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server run the same function, so the same input gives the same answer in both.
