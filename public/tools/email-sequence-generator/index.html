Email Sequence Generator

Generate multi-touch email sequences by persona, stage, and objective. Creates prospecting, nurture, follow-up, and re-engagement sequences.

By Shashwat Ghosh, founder of Helix GTM Consulting · Last updated 25 September 2026

What do I need to run Email Sequence Generator?

Free, no sign-up, no account. A web browser is enough; the answer comes back in a second or two.

Sequence Tips

Timing:

  • Day 1 → 3 → 7 → 12 → 17
  • Adjust based on response patterns

Subject Lines:

  • Keep under 50 characters
  • No spam trigger words
  • Personalization when possible

Best Practices:

  • Research before sending
  • Personalize at least one element per email
  • Track open and reply rates
  • A/B test subject lines

Who is Email Sequence Generator not ideal for?

  • Anyone who cannot give the required inputs (Sequence type, Target persona, Your solution); the answer is built only from them.
  • Teams that want the tools to read their CRM, email or call notes: they work only from what you type.
  • Sending anything straight to a buyer: every output is a draft for a person to review first.

How do I use Email Sequence Generator from Claude?

Connect Revenue Enablement once (see Connect), then ask in plain words. A prompt built from the tested example:

Use Revenue Enablement's Email Sequence Generator tool. sequence type: cold outreach; target persona: Clinic operations directors; your solution: ClinicFlow scheduling; num emails: 3; tone: professional.

MCP tool name: email_sequence_generator. REST: POST https://revenue-enablement.gtmhelix.com/api/tools/email_sequence_generator with this JSON body (see Docs):

{
  "input": {
    "sequence_type": "cold_outreach",
    "target_persona": "Clinic operations directors",
    "your_solution": "ClinicFlow scheduling",
    "num_emails": 3,
    "tone": "professional"
  }
}

How does Email Sequence Generator work?

It applies fixed rules in the Revenue Enablement code to the inputs above and returns text. It does not call an AI model, does not look anything up, and does not store what you type. The web form and the MCP server run the same function, so the same input gives the same answer in both.
